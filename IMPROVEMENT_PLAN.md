# План розвитку MyCV у сайт, що системно приносить ліди

## Ціль

Перетворити сайт із портфоліо на вимірювану воронку: цільовий трафік → довіра → заявка → швидка обробка → продаж.

Головні метрики:

- кількість валідних заявок за 30 днів;
- конверсія відвідування → заявка;
- частка органічного трафіку та заявок із Google;
- кількість запитів і сторінок у Google Search Console;
- LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 на 75-му перцентилі;
- час першої відповіді на заявку.

## P0 — вимірювання та надійність ліда

- [x] Перебудувати головну сторінку й мобільний UX.
- [x] Перевірити форму, клавіатурну навігацію та адаптивність.
- [x] Зберігати landing page, referrer, UTM та тривалість заповнення разом із заявкою.
- [x] Додати honeypot і серверний allowlist/обмеження довжини полів.
- [x] Реєструвати успішну заявку в серверній та GA4-аналітиці.
- [x] Показувати в адмінці кількість лідів і конверсію.
- [x] Екранувати дані в email та адміністративній статистиці.

## P1 — технічне SEO та індексація

- [x] Узгодити robots.txt, canonical і sitemap; не додавати noindex-сторінки в sitemap.
- [x] Додати коректні Open Graph/Twitter метадані на основні публічні сторінки.
- [x] Залишити structured data лише там, де вона відповідає видимому контенту.
- [x] Додати посадкові сторінки для лендінгу, сайту-візитки та QR-меню.
- [x] Додати серверний HTML для статей, списку робіт і окремих сторінок проєктів, щоб основний контент не залежав від JS-рендерингу.
- [x] Побудувати внутрішні посилання між головною, послугами, роботами та формами заявки.

## P2 — конверсія і довіра

- [ ] Перетворити портфоліо на окремі кейси: задача, процес, результат, строки, відгук.
- [ ] Додати реальні бізнес-результати тільки там, де є підтверджені дані.
- [x] Додати короткий кваліфікаційний сценарій та очікуваний строк відповіді.
- [x] Додати видимий Telegram fallback, якщо API заявки недоступний.
- [ ] Підготувати follow-up лист після заявки та нагадування про незакриті ліди. (Ручні нагадування та контроль першої відповіді вже додані; автоматичний follow-up ще попереду.)

## P3 — швидкість і стабільність

- [ ] Виміряти Lighthouse та польові Core Web Vitals після публікації.
- [ ] Самостійно хостити критичні шрифти, оптимізувати LCP-зображення й кешування.
- [x] Додати healthcheck, перевірене резервне копіювання даних заявок і контроль доставки Telegram/email.
- [x] Додати автоматичні smoke-тести для головної, SEO-посадкових, SSR-контенту, sitemap, редиректів і health API.

## P4 — контент і зростання

- [ ] Створити кластери статей під проблеми ніш: психологи, фотографи, кафе, майстри, тренери.
- [ ] Додати локальні сторінки лише для реальних регіонів роботи, без doorway-контенту.
- [ ] Налаштувати Search Console, GA4 conversions та щомісячний перегляд запитів.
- [ ] Тестувати офер, CTA і структуру форми на фактичних даних, а не на припущеннях.

## Принципи

- Не вигадувати відгуки, цифри або кейси.
- Не створювати масові дубльовані SEO-сторінки.
- Не вважати позицію в Google гарантованою: сайт створює технічну основу, а результат залежить також від попиту, конкуренції, контенту, посилань і часу.
- Кожне покращення має або підвищувати видимість, або довіру, або конверсію, або надійність обробки заявки.
